[https://storage.yandexcloud.net/clining-preview-bogdasovandrej-20260920/preview.html?v=20260925](https://storage.yandexcloud.net/clining-preview-bogdasovandrej-20260920/preview.html?v=20260925)

Страница позволяет позвонить по рабочему номеру или написать в личный Telegram по номеру; формы сбора персональных данных нет. Кнопки будущих ботов неактивны. API на этот бакет автоматически не выкладывается.

План: собственный домен с HTTPS → Yandex Object Storage в регионе Россия. Публичный API: Yandex API Gateway + Cloud Functions. База записей и расписания — в РФ. GitHub не участвует в обслуживании запросов посетителей.

## Что подготовлено

- CI собирает и проверяет сайт, сохраняет `dist` как артефакт GitHub Actions.
- Ручной workflow загружает проверенную сборку в Yandex Object Storage через S3-совместимый API.
- HTML и JS публикуются с `Cache-Control: no-cache`, чтобы браузер перепроверял актуальность формы.
- Загрузка не удаляет существующие объекты. `index.html` загружается последним; обновление нескольких файлов не является атомарным.
- Облачные ресурсы, домен и сертификат этим workflow не создаются. Демонстрационный бакет выше создан вручную и не является production-хостингом.

## Настройка перед первым релизом

1. Создать отдельный бакет сайта в российском регионе, настроить `index.html` как главную страницу, доступ на чтение файлов сайта, домен и HTTPS. Для данных клиентов использовать отдельное закрытое хранилище.
2. Создать сервисный аккаунт с правами загрузки только в бакет сайта. Его статический ключ не хранить в исходниках и не отправлять в чат.
3. В GitHub Environment `production` задать secrets `YC_ACCESS_KEY_ID`, `YC_SECRET_ACCESS_KEY`, variable `YC_BUCKET` с именем бакета. В переменных репозитория установить `YC_DEPLOY_ENABLED=true` после подготовки к релизу.
4. Заполнить контакты, домен, реквизиты оператора, реализовать и проверить backend. `npm run check:release` блокирует текущие известные заглушки, но не заменяет проверку бизнес-процессов.
5. В Actions вручную запустить `Deploy to Yandex Object Storage` из `main`. Перед публикацией workflow снова выполняет сборку и проверки.
6. Проверить главную, HTTPS, `/slots` и создание реальной тестовой записи без VPN через мобильную и домашнюю сети. Отдельно проверить получение уведомлений и чтение записи в планере.

Автоматическую публикацию после push подключить после первого проверенного релиза. На текущем этапе push запускает только CI.
