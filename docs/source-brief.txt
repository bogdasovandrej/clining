Ты senior full-stack разработчик, дизайнер и SEO-специалист. Нужно с нуля создать современный, быстрый и законный сайт для самозанятой специалистки по клинингу и химчистке в Екатеринбурге.

Контекст старого успешного проекта:
- Первый проект: сайт студии красоты «Море красок» на more-krasok.ru.
- Статический сайт лежит на GitHub Pages, деплой через GitHub Actions после push в main.
- Backend записи и боты живут на Cloudflare Workers, потому что оттуда доступны Telegram и MAX.
- Для пользователей из РФ прямой workers.dev рискован: нужен российский публичный API через Yandex API Gateway/Yandex Cloud Function, который проксирует публичные маршруты на Cloudflare.
- Персональные данные россиян нельзя хранить в Cloudflare. Имя, телефон, заметки хранить в РФ: закрытый Yandex Object Storage/S3 или другой российский контур, доступ только по PD_KEY. В Cloudflare/D1 хранить только неперсональные данные: дата, время, услуга, статус, id записи, client_chat/client_kind.
- База расписания и записей: Cloudflare D1, не KV. KV нельзя использовать для графика и бронирования из-за eventual consistency.
- Публичные маршруты: GET /schedule.json, GET /slots, GET /busy, POST /book.
- Приватные маршруты: /planer/data, /planer/add, /planer/cancel по ключу; /pd/* только по X-Pd-Key.
- Боты: 4 штуки — Telegram мастер, Telegram клиентский, MAX мастер, MAX клиентский.
- Мастер-бот: график, записи, блокнот, планер, календарь на телефон.
- Клиентские боты: выбрать услугу → день → время → имя/телефон → запись → напоминание за сутки.
- MAX медленнее Telegram: тяжёлые календарные UI и управление графиком лучше делать в Telegram и web-планере; в MAX оставить надёжные действия и ссылки.
- Личный календарь: /calendar.ics по секретному ключу, чтобы записи можно было подписать в календаре телефона.
- Планер: отдельная страница planner/planer с ключом, удобная для мастера, показывает день, записи, имена, телефоны, отмену, ручное добавление.
- В старом проекте была ошибка: скрытое honeypot-поле website могло вернуть fake ok без записи. В новом проекте не делать скрытую ловушку, которая может дать ложный успех пользователю.
- Любая отправка формы должна показывать успех только после реального подтверждения backend: ok true и id записи.
- Для нестабильной сети нужны таймауты, повтор, понятная ошибка и fallback “позвонить/написать”.
- Не кэшировать HTML/JS формы агрессивно. Service Worker — только если строго контролируется и не ломает запись.

Техническая архитектура:
- Статика: GitHub Pages или российский статический хостинг. Если GitHub Pages работает для целевой аудитории — можно оставить; если нужен максимум РФ-надёжности — рассмотреть Yandex Object Storage static hosting.
- Backend: Cloudflare Worker для Telegram/MAX API и основной логики.
- Российский фасад: Yandex API Gateway + Cloud Function для публичных запросов сайта и /pd/*.
- DB: Cloudflare D1 для расписания/слотов/статусов.
- PD: Yandex Object Storage/S3 или российская БД для имени, телефона, адреса, комментария.
- Единый source of truth: prices.json/services.json. Из него генерировать сайт, ботов, schema.org и посадочные страницы.
- Не дублировать цены руками в 5 местах.
- Обязательные проверки: POST /book, CORS, preflight, /slots, /busy, создание записи, отмена, уведомления TG/MAX, запись ПДн в РФ, чтение планера.
- Добавить /diag только для администратора: состояние TG/MAX webhooks, PD storage, DB, Yandex proxy, время ответа.
- Добавить таймауты fetch на сайте: 8-10 секунд, понятная ошибка, кнопка “позвонить/написать”.
- При успехе backend должен возвращать ok:true, id, start, end. Сайт показывает успех только при этом.
- Не использовать honeypot, который возвращает fake ok клиенту.
